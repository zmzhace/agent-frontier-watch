# 03 · 可验证搜索与 Agentic Evolution

## 核心思想

当一个候选答案可以被自动、便宜、可靠地评分时，LLM 最有价值的角色未必是一次给出正确答案，而是持续提出有希望的候选：

```text
生成候选 → 执行 → 自动评分 → 诊断失败
   ▲                              │
   └──── 保留经验、变异和重组 ────┘
```

这种“生成器 + 评估器 + 搜索循环”正在成为算法发现、代码优化和 Agent 工作流设计的共同范式。

## AlphaEvolve：从研究演示进入真实基础设施

AlphaEvolve 使用 Gemini 生成和修改程序，再由自动评估函数筛选候选。Google DeepMind 在 2026 年更新中报告：

- 它已成为 Google 内部基础设施的一部分，用于下一代 TPU 设计；
- 某些缓存策略优化从数月人力缩短到两天；
- 在电网优化案例中，将模型找到可行解的比例从 14% 提高到 88% 以上；
- 在量子模拟案例中，找到误差比传统基线低约 10 倍的电路。

- 来源：[AlphaEvolve: How our Gemini-powered coding agent is scaling impact](https://deepmind.google/blog/alphaevolve-impact/)
- 论文：[AlphaEvolve: A coding agent for scientific and algorithmic discovery](https://arxiv.org/abs/2506.13131)
- 证据等级：论文结果 **A/C**（视具体结果的复现状态）；2026 应用披露 **B**

## 2026 年的新变化：搜索器也开始自我改进

早期系统通常使用人工写死的“生成—评分—变异”流程。新的 Agentic Evolution 工作开始让元 Agent 修改搜索过程本身。

### AEvo

AEvo 不直接生成下一个候选，而是编辑控制后续演化的程序或 Agent 上下文，使积累的证据能影响长程搜索，同时减少通用 Agent 在多轮迭代中的漂移。

- 论文：[Harnessing Agentic Evolution](https://arxiv.org/abs/2605.13821)
- 证据等级：**C**

### AlgoEvo

2026-09-14 发布的 AlgoEvo 强调分层经验库：系统从运行反馈中提取方法、失败模式和可迁移经验，再用这些经验指导后续算法搜索。这意味着状态不再只是“当前最优代码”，还包括搜索过程中学到的方法论。

- 论文：[AlgoEvo: Self-Evolving Agentic Search for Automated Algorithm Discovery](https://arxiv.org/abs/2609.15820)
- 证据等级：**C**

## 为什么验证器比生成器更关键

只要评分函数存在漏洞，搜索系统就会找到“骗分”而不是真正更好的方案。可验证搜索能否扩展，取决于评估器是否具有：

- **正确性**：评分与真实目标一致；
- **抗投机性**：候选不能利用测试集或环境漏洞；
- **覆盖度**：不仅衡量速度，也衡量正确、安全和可维护性；
- **成本优势**：验证必须比人工发现答案便宜；
- **迁移验证**：改进在新输入、新规模和新环境中仍成立。

这也是为什么算法、数学和代码优化领先于开放式产品研究：前者往往有编译器、测试、模拟器或明确目标函数。

## 与 RSI 的关系

可验证搜索是当前最可信的局部自我改进机制，但它不自动等于完整 RSI：

- 人类通常仍然定义问题和评分函数；
- 搜索空间受到人工设计的表示和工具限制；
- 得到的新程序未必能提升生成模型本身；
- 局部指标改善可能损害系统的其他能力。

真正的跃迁将发生在系统不仅搜索答案，还能可靠地改进自己的评估器、搜索策略和训练过程时。
