# 02 · Jev 与专用决策模型

## Jev 是什么

TypeSafe AI 于 2026-09-15 发布 Jev，并将其定义为首个公开的 **System One Model**。它不逐 Token 生成任意文本，而是接收上下文和候选选项，直接返回结构化选择及概率。

典型用途包括：

- 在大量工具中选择下一项工具；
- 请求分类与模型路由；
- 内容审核、权限判断与升级人工；
- 给候选结果打分或充当 Agent evaluator；
- 在高频、低延迟循环中做状态决策。

- 官方来源：[Introducing System One Models & Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- 证据等级：**B**

## 为什么值得关注

今天许多 Agent 用同一个生成式 LLM 完成所有工作：理解请求、选择工具、构造参数、生成内容、判断结果。这样做灵活，但速度、成本和输出约束都不理想。

Jev 所代表的架构是把 Agent 拆开：

```text
快速决策层：分类、路由、是否继续、风险等级
      ↓
慢速生成层：复杂推理、写代码、写文本、构造参数
      ↓
验证决策层：通过、重试、换模型、转人工
```

如果这种分工成立，大模型将不再承担每一次细粒度判断。高频控制面由便宜、稳定的专用模型处理，昂贵模型只在确实需要开放式生成时出场。

## 截至 2026-09-21 的证据

TypeSafe 声称，Jev 在其工作流评测中最高达到约 193.6 倍速度和 444.6 倍成本优势，并通过模型接口保证 Schema 匹配。但需要注意：

- 工作流由 TypeSafe 团队制作；
- 参考答案由其他前沿模型组合产生；
- 没有公开传统通用基准成绩；
- “结构保证”不等于“语义判断正确”；
- 产品仍处于 early access。

一个独立、可复现的早期测试仓库已经开始记录真实 API 的成本、延迟和原始输出，但样本范围仍小，尚不足以建立通用结论。

- 独立早期测量：[WallerChen/jev-measured](https://github.com/WallerChen/jev-measured)
- 官方工作流评测：[TypeSafe Workflow Evals](https://evals.typesafe.ai/)
- 证据等级：官方数字 **B**；独立小样本 **C**

## Jev 不是什么

- 它不是通用文本生成模型；
- 它不能替代需要创造、解释或长程推理的 LLM；
- 它不是证明“System 1 比 System 2 更智能”的实验；
- 固定 Schema 只能消除格式类幻觉，不能自动消除错误判断；
- 截至本次核验，没有足够公开证据证明它在广泛任务上优于经过优化的小模型或分类器。

## 真正要观察的指标

未来判断这条路线是否成立，应关注：

1. 与小型 LLM、encoder classifier 和规则系统的同口径准确率；
2. 概率校准误差，而不仅是 top-1 命中率；
3. 候选数增长时的性能和延迟；
4. 分布漂移、对抗输入和提示注入下的鲁棒性；
5. 在完整 Agent 工作流中对总成本和最终成功率的影响；
6. 是否支持本地部署、微调、审计和版本固定。

Jev 目前最重要的贡献，是把“Agent 的决策接口应该是什么”重新变成一个独立问题。
